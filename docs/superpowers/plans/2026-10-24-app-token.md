# Optional APP_TOKEN Implementation Plan

> **For agentic workers:** Use subagent-driven-development for the independent backend and transport tasks; integrate the React session gate in the current session. Use TDD and review the complete change before delivery.

**Goal:** Protect every API request with optional Bearer authentication while preserving the default LAN deployment and all disabled write capabilities.

**Architecture:** Authentication wraps the API handler before routing or path normalization. The browser validates capabilities before mounting its dashboard. A shared credential module supplies REST and fetch SSE headers; credentials are persisted only in sessionStorage.

**Tech Stack:** Go net/http, SHA-256 and crypto/subtle; React 19, TanStack Query, native fetch/ReadableStream and AbortController.

**Spec:** The user's APP_TOKEN task, plus `docs/spec-20260921-mvp.md` and `AGENTS.md`.

## Global Constraints

- APP_TOKEN is optional, empty means LAN mode; do not trim credentials.
- Public health and assets; authenticate unknown and normalized/encoded API paths.
- Uniform 401: UNAUTHORIZED / Authentication required / retryable false; no token disclosure.
- No new state library, offline data, write capabilities or executors.
- Preserve existing uncommitted UI work and use English function comments.
- Only `unraid-mobile.app-token` in sessionStorage may persist credentials; never URL/query keys/logs.

## Review Focus

- Late 401s from aborted requests must not invalidate a newer credential session.
- Clearing authentication must cancel queries, close streams and discard protected cache.
- Heartbeats and unused SSE events must keep healthy streams alive.
- Split CRLF and UTF-8 across chunks must parse without false reconnection.
- Authenticated malformed paths must preserve existing Operation path validation.
