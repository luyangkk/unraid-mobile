# Installable PWA and Offline Shell Implementation Plan

> **For agentic workers:** Use executing-plans for implementation and requesting-code-review for a final independent review.

**Goal:** Install Unraid Mobile and open its static shell offline without persisting any business data or credentials.

**Architecture:** vite-plugin-pwa injectManifest generates a revisioned static precache and a custom Service Worker. Only canonical same-origin static requests and browser client navigations can use it. A registration controller outside SessionGate exposes an optional update banner; activation and reload require a user action.

**Tech Stack:** Existing React 19 / Vite 6 / Go 1.24; add vite-plugin-pwa and its Workbox dependencies only.

**Spec:** User's “实现可安装 PWA 和离线应用壳” requirements, 2026-10-25.

## Global Constraints

- Root manifest `/manifest.webmanifest`, worker `/sw.js`, scope `/`, start URL `/`.
- Static shell stays public; API, health, SSE and Operation are network only even in LAN mode.
- No API runtime cache, external cache, credentials, Background Sync, Push or writes.
- Do not upgrade existing dependencies or overwrite existing staged Docker changes.
- Development defaults to no Service Worker; errors must not block rendering.
- All code functions receive English function-level comments.

## Design Decisions

Use injectManifest instead of generateSW: an explicit fetch boundary can reject encoded paths, credential-bearing requests and all nonstatic requests before touching Cache Storage. Do not use a standalone hand-maintained worker: Vite must inject the build's asset revisions. Precache all route chunks so a first successful visit installs the entire shell. Navigations use the installed version's index; missing assets remain network failures. Set a cache suffix derived from precache revisions and delete prior application static caches on activation.

Keep registration and update state outside protected route content so an update can be offered on a connection-error or token screen. Only the Refresh action sends `SKIP_WAITING`; only its subsequent controller change reloads, once. Dismissing a banner keeps the current worker active.

Existing SessionGate already preserves saved tokens after transport failure and denies protected queries until capabilities succeeds. Retain this behavior; add an online-event retry for offline cold boot instead of introducing offline data admission.

Review rulings: migrate only old built JS/CSS into the activated cache before deleting old cache names, so tabs that have not refreshed can still import their original chunks. Download all install responses before cache writes and reuse a complete same-revision cache. If another tab has already activated an offered update, explicit Refresh reloads directly, once.

Cleanup uses Cache Storage creation order: only caches preceding the current
cache are retired, leaving later installing versions alone. Failed migration
retains its source, and old JS/CSS can be read from preceding application
caches without runtime writes or business-response fallback.

## Review Focus

- Encoded API paths, nested `api` segments, query credentials and Authorization-bearing requests must never receive cached HTML.
- A second tab accepting an update must not reload this tab without consent.
- Route chunks must be precached even if the first visit was only to Home.
- Offline cold boot preserves credentials and recovers capabilities before protected data.
- Versioned caches must retain the active shell until consent and clean up obsolete caches on activation.
