# PWA Local Validation — 2026-10-25

The production build meets Chrome's manifest and installability checks. All
four client routes load the static shell offline. This does not establish
Android/iOS installation or real Unraid HTTPS compatibility.

## Automated Checks

- `npm ci`: passed. Every pre-existing lockfile package retains its version.
- `npm test`: 18 files, 221 tests passed.
- `npm run build`: passed, including the executable PWA artifact verification.
- `npm run verify:pwa`: passed. Valid root manifest, five opaque PNGs, checked
  dimensions/borders/maskable safe circle, and 12 local static precache entries.
- Generated worker checks: all route chunks installed; client navigations
  return the shell; API/health/SSE/Operation, credentials, external URLs and
  malformed paths never access Cache Storage. Missing assets remain network
  failures. Old cache names are deleted after static chunk migration. Failed
  installation preserves the active cache; worker-only updates reuse it.
  Activation leaves later-created installing caches alone; a quota failure
  preserves the source cache and old chunks remain readable offline.
- `go test -race ./...`: passed.
- `go build ./cmd/server` and `go build ./cmd/host-spike`: passed, with output
  binaries directed to `/tmp`.
- `gofmt`, Unraid XML parse, manifest JSON parse, shell syntax check and
  `git diff --check`: passed.
- The image script's public PWA resource function passed against the actual Go
  frontend handler serving `web/dist`, with authentication enabled. Manifest,
  worker MIME/cache headers, all icons, direct routes and missing assets passed.
  This was a handler check, not an image check.

## Chrome Production-Build Checks

Used local Chrome with a disposable persistent browser profile, the production
Go frontend handler, `web/dist`, and synthetic host/container/VM readers.
Browser scripts, profiles and intermediate output stayed under `/tmp`.

- Chrome DevTools Protocol reported no manifest errors or installability errors.
  The worker URL is `/sw.js` and its scope is `/`.
- Actual Cache Storage contained one versioned application cache and 12 local
  static entries, including lazy route chunks. No API response, Authorization
  header or token appeared there.
- The running offline page retained stale in-memory samples and its existing
  session token.
- Cold offline navigation to `/`, `/docker`, `/vm`, `/storage` and an unknown
  client route loaded the shell and connection-error screen without a token
  form or restored business samples.
- Offline API, health and missing asset navigation failed through the network.
  Authenticated unknown API returned JSON 404 online; missing assets returned
  404, with no HTML fallback or cache insertion.
- Cold-boot network recovery validated Capabilities, fetched System, then
  opened exactly one SSE. CDP's network-state override was needed to emit the
  browser `online` transition reliably after repeated cached navigations.
- Portrait widths of 320px/390px and 844px landscape had no horizontal overflow;
  bottom navigation stayed inside the viewport with targets at least 44px tall.
- A second worker version reached waiting and displayed the update banner.
  User confirmation activated it and reloaded exactly once. A second tab that
  dismissed the banner was not reloaded.
- No JavaScript page errors were observed.

## Remaining Manual Checks

Docker was unavailable, so image build, full image smoke verification and
`docker compose config` were not run.

Add to Home Screen, Apple icon/title, physical safe areas/Home Indicator,
real-device background recovery and a real Unraid HTTPS/reverse-proxy setup
