本文把 MVP 计划中的技术决定落成工程约束。产品范围、页面信息架构和交互细节以计划文档为准；本文不扩展 V1 功能。

## 目标与边界

系统面向局域网或受控私网中的单台 Unraid 主机，提供手机端实时状态查看和基础运维操作。

V1 必须完成：

- 主机 CPU、内存、网络和温度的实时展示。
- Docker 容器的列表、状态、资源统计与启停重启。
- VM 的列表、状态与启停、强制停止。
- Array、Parity、Pool、Disk 的状态展示；已验证的 Array / Parity 操作。
- 单次操作的异步状态与失败信息。
- iOS / Android 浏览器及安装后的 PWA 使用体验。

V1 不做：多主机管理、账户体系、通用 Shell、Docker 编辑、Share 管理、设置管理、历史监控与 API 数据离线缓存。

## 总体架构

```text
手机浏览器 / PWA
        │ HTTPS 或 HTTP（受控网络）
        ▼
Go 服务进程（容器 PID 1）
├── 静态文件：React PWA
├── HTTP API：快照与操作提交
├── SSE：状态增量与操作进度
├── Metrics Sampler：主机指标采样
├── Operation Manager：异步操作编排
├── Capability Detector：运行环境探测
└── Adapters
    ├── procfs / sysfs
    ├── Docker Engine API
    ├── libvirt
    └── Unraid Array / Parity / Storage Provider
        │
        ▼
Unraid Host
```

React 只在构建阶段运行。`vite build` 生成的静态文件会通过 `go:embed` 编入 Go 二进制，由同一个 Go 服务提供；生产环境不运行 Vite，也不需要第二个 Web Server。

## 运行和部署

### Docker 镜像

镜像采用三阶段构建：Node 构建前端，Go 构建服务，最小运行镜像只包含 Go 二进制和必要运行依赖。容器入口只启动 Go 二进制。

```text
Node build → web/dist
Go build + go:embed(web/dist) → /app/server
runtime → /app/server
```

### 容器权限与挂载

主应用只读验收保持 `Privileged=false`，不需要高权限容器。生产部署以 `deploy/unraid/unraid-mobile.xml` 和 README 为准，不以尚未实现的控制接口为由扩大权限或挂载范围。

以下为只读挂载示意。Docker socket 为可选项；VM 验收仅在明确授权的目标主机上增加只读 libvirt 目录挂载，并显式开启读取。读取成功不授予写权限。

```yaml
services:
  unraid-mobile:
    image: ghcr.io/<owner>/unraid-mobile:latest
    container_name: unraid-mobile
    privileged: false
    ports:
      - "8080:8080"
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
      - /var/local/emhttp:/host/var/local/emhttp:ro
      # 可选：Docker 只读展示
      # - /var/run/docker.sock:/var/run/docker.sock:ro
      # 可选：VM 目标主机验收，仅使用 libvirt-sock-ro
      # - /var/run/libvirt:/var/run/libvirt:ro
    environment:
      TZ: Asia/Shanghai
      VM_READ_ENABLED: "false"
      # APP_TOKEN: optional-long-random-token
    restart: unless-stopped
```

`/host/proc` 和 `/host/sys` 是读取主机数据的固定入口。所有代码不得混用容器自身的 `/proc` 与主机的 `/host/proc`。

只读 socket 挂载本身不限制 API 权限，应用只能发送固定读取请求。不得为人工验收挂载整个 `/boot`、用户数据目录或可写 socket。

### 网络与认证

默认使用局域网、Tailscale 或 WireGuard 暴露服务，不支持裸公网部署。`APP_TOKEN` 未设置时按 LAN 模式运行；设置后，除健康检查外的 API 都要求：

```http
Authorization: Bearer <APP_TOKEN>
```

前端把 token 仅保存在当前浏览器的 session storage 中。当前主应用已支持可选 `APP_TOKEN`；人工验收启用认证时，API 使用相同 Bearer Header，不把凭据写入 URL 或验收记录。

## 后端模块与依赖规则

```text
cmd/server                 进程入口、依赖装配、生命周期管理
internal/api               HTTP 路由、认证、中间件、DTO、SSE
internal/app               业务用例与领域模型
internal/adapter           外部系统实现
internal/capability        能力探测与结果模型
internal/event             事件 Hub、订阅与 SSE 编码
internal/metrics           周期采样与短时内存窗口
internal/platform          受限文件系统与受限命令执行能力
web                        React 源码和构建产物
```

依赖方向固定为：`api → app → adapter/platform`。`app` 只依赖接口和领域模型，不能导入任何 Unraid 专有路径、WebGUI 解析逻辑或 Docker / libvirt 客户端。

```go
type ArrayController interface {
    State(ctx context.Context) (ArrayState, error)
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
}
```

Provider 通过运行时探测选择，不以 Unraid 版本号分支业务逻辑：

```text
启动 → Capability Detector → 依次 Probe Provider → 选中第一个可用实现
```

版本号只记录在状态和诊断信息中。Provider 选择失败时，相关能力标记为不可用，页面保留并说明原因。

## 数据采集与刷新

采样仅为计算瞬时速率和给 UI 提供短时趋势，不是历史监控。服务重启或浏览器重新打开后，趋势从头开始；不接入 Prometheus、InfluxDB 或其他时序数据库。

| 数据 | 主数据源 | 周期 |
|---|---|---:|
| CPU 使用率 | `/host/proc/stat` | 1 秒 |
| 内存 | `/host/proc/meminfo` | 1 秒 |
| 网络速率 | `/host/proc/net/dev` | 1 秒 |
| Docker 统计 | Docker Engine API | 2 秒 |
| VM 状态 | libvirt | 3 秒 |
| 磁盘 I/O | `/host/proc/diskstats` | 2 秒 |
| CPU 温度 | `/host/sys/class/thermal`、`hwmon` | 3 秒 |
| 磁盘温度 | 由 Provider 决定 | 10 秒 |
| Array / Parity 状态 | Unraid Provider | 5 秒 |
| 容量 | Storage Provider | 30 秒 |

采样器保留最新值和最多 60 个时间点。CPU 使用率、网络速率和 I/O 均使用相邻样本的 delta 计算。温度传感器必须先探测标签和设备，不能假定 `thermal_zone0` 是 CPU。

浏览器进入后台时，前端关闭高频 SSE 订阅；重新可见后重新拉取快照并建立订阅。服务端即使没有订阅者也继续维持必要的轻量采样，保证重新连接后的首个快照完整。

系统指标首版实现约定：CPU 使用率和网络速率在首个样本、计数器回退或采集恢复时返回 `null`。内存使用量采用 `MemTotal - MemAvailable`。网络从 `/host/proc/1/net/route` 选择有效且 metric 最低的默认 IPv4 路由，只统计该接口在 `/host/proc/1/net/dev` 中的计数器，避免 `/proc/net` 的当前进程命名空间和网桥成员重复统计。不存在有效接口或读取失败时，网络字段为空并说明原因。

`GET /system` 和 `system.metrics` 的数据包含 `timestamp`、`available`、`reason`、`hostname`、`uptimeSeconds`、`cpuUsage`、`cpuTemperature`、`memoryUsedBytes`、`memoryTotalBytes`、`networkInterface`、`networkRXRate`、`networkTXRate`、`diagnostics`。`available` 表示 CPU 和内存的核心采集可用；可选温度或网络缺失通过 `diagnostics` 单独表达。未挂载宿主机数据时不回退到容器数据。名称使用可选 `SERVER_NAME` 或挂载的宿主机 hostname 文件，未知时由 UI 显示 Unraid。

## HTTP API

API 前缀固定为 `/api/v1`。所有 JSON 字段使用 camelCase；容量和速率使用原始字节数，展示格式只在前端处理；时间使用 RFC 3339 UTC 字符串。

### 快照接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/capabilities` | 当前主机可读取和可操作的能力 |
| GET | `/status` | 后端与外部连接概况 |
| GET | `/system` | 主机信息和最新指标 |
| GET | `/docker` | 容器列表和汇总 |
| GET | `/vms` | VM 列表和汇总 |
| GET | `/storage` | Array、Parity、Pool、Disk 概览 |
| GET | `/operations/{operationId}` | 单个异步操作的当前状态 |
| GET | `/events` | SSE 事件流 |

`GET /healthz` 不属于 API 前缀，只回答进程是否存活，成功时返回 `204 No Content`。它不得检查 Docker、libvirt 或任何 Unraid Provider。

Storage 只读首版通过 `/host/var/local/emhttp/disks.ini`、`var.ini` 获取 Array、Parity、Pool 和 Disk 状态，并通过 `/host/proc/diskstats` 计算磁盘 I/O。新增只读挂载 `/var/local/emhttp:/host/var/local/emhttp:ro`，不需要挂载用户数据目录。`GET /storage` 返回 `timestamp`、`available`、`reason`、`source`、`array`、`parity`、`pools`、`disks`、`diagnostics`；容量对象使用 `totalBytes`、`usedBytes`、`freeBytes`。每个 Disk 的 `powerState` 根据 Unraid `spundown` 元数据映射为 `active`、`standby` 或 `unknown`。休眠硬盘的温度为 `null`，UI 明确显示休眠状态且不得为获取温度主动唤醒磁盘。Array 汇总排除 Parity、Flash 和 Pool，Pool 容量只计一次，Btrfs 有效容量采用元数据中的已用与可用之和。阵列停止或数据不完整时容量为 `null`，不输出部分磁盘之和作为全阵列容量。`storage.read`、`array.read`、`parity.read` 随实际读取结果返回；写能力保持关闭。此版 Storage 页面每两秒读取一次服务端缓存快照，后台暂停，不缓存离线业务数据；后续可迁移到 Storage SSE 事件。

### 操作接口

以下为后续写操作设计，不是当前可用接口清单。人工验收不提交这些请求；当前所有写能力默认关闭，没有真实执行器。

| 方法 | 路径 | 操作 |
|---|---|---|
| POST | `/docker/{id}/start` | 启动容器 |
| POST | `/docker/{id}/stop` | 停止容器 |
| POST | `/docker/{id}/restart` | 重启容器 |
| POST | `/vms/{id}/start` | 启动 VM |
| POST | `/vms/{id}/stop` | 正常关机 VM |
| POST | `/vms/{id}/force-stop` | 强制停止 VM |
| POST | `/array/start` | 启动 Array |
| POST | `/array/stop` | 停止 Array |
| POST | `/parity/start` | 启动 Parity Check |
| POST | `/parity/cancel` | 取消 Parity Check |

操作请求只接受资源 ID 和固定动作，不接受任意命令、路径、参数或脚本。资源 ID 必须存在于对应 Adapter 已知的资源列表中；不存在返回 `404`，不支持的动作返回 `409`。

成功受理统一返回 `202 Accepted`：

```json
{
  "operationId": "op_01J...",
  "accepted": true
}
```

### 核心响应模型

以下保留原设计示例，不代表当前响应字段或已授予的能力；当前契约见 README 和实际代码。示例中的写能力不能用于开启操作。

`GET /capabilities`：

```json
{
  "docker": true,
  "vm": true,
  "array": { "read": true, "start": true, "stop": true },
  "parity": { "read": true, "start": true, "cancel": false },
  "storage": { "temperature": true, "io": true }
}
```

`GET /status`：

```json
{
  "server": "online",
  "docker": "connected",
  "libvirt": "connected",
  "arrayProvider": "webgui"
}
```

所有失败响应采用同一结构：

```json
{
  "error": {
    "code": "DOCKER_RESTART_FAILED",
    "message": "Couldn't restart Plex",
    "details": "permission denied",
    "retryable": true
  }
}
```

`message` 可直接展示给用户；`details` 只在“技术详情”折叠区显示。错误代码用于前端行为和测试，不用 HTTP 状态码字符串代替。

## SSE 事件协议

客户端固定按以下顺序连接：先请求所需快照、完成首屏渲染、再连接 `/api/v1/events`。重连后再次请求快照，避免依赖未送达的增量事件。

事件通过标准 SSE 的 `event` 和 `data` 字段发送：

```text
event: system.metrics
data: {"timestamp":"2026-09-21T01:00:00Z","cpuUsage":23.4,"memoryUsedBytes":1234}
```

V1 事件类型：

| 事件 | 内容 |
|---|---|
| `system.metrics` | CPU、内存、网络、CPU 温度 |
| `docker.stats` | 容器 CPU、内存、网络统计批次 |
| `docker.state` | 单个容器状态变化 |
| `vm.state` | 单个 VM 状态变化 |
| `storage.io` | 磁盘 I/O 变化 |
| `array.state` | Array 状态变化 |
| `parity.progress` | 进度、速度、ETA 和状态 |
| `operation.updated` | 异步操作状态变化 |
| `capabilities.updated` | Provider 或外部连接变化 |

SSE 不推送完整服务器快照。Docker 统计由服务端聚合为批次发送，禁止为每个容器各开一个连接。服务端每 15 秒发送一次注释心跳，便于代理和浏览器保持连接。

## Operation 模型

任何有副作用的动作都创建 Operation。HTTP 请求只负责校验和入队，操作在受控 worker 内执行；同一资源同一时刻只允许一个运行中的 Operation。

```go
type Operation struct {
    ID        string
    Type      string
    Resource  string
    State     OperationState
    StartedAt time.Time
    EndedAt   *time.Time
    Progress  *float64
    Error     *OperationError
}
```

状态机如下：

```text
pending → running → success
                  ├→ failed
                  └→ cancelled
```

`pending` 和 `running` 状态通过 `operation.updated` 推送。Array / Parity 只有在后端能可靠观察到实际步骤时才展示步骤；无法确认的进度只显示“正在执行”，禁止伪造阶段。

Operation 仅保存在内存中，保留最近 100 条或最多 24 小时。服务重启后，前端根据重新拉取的资源快照恢复真实状态，不把丢失的内存操作误报为失败。

## Adapter 约束

### Docker

通过挂载的 `/var/run/docker.sock` 调用 Docker Engine API，使用 SDK 或 HTTP API；不得调用并解析 `docker ps`、`docker stats` 等 CLI 输出。支持 list、inspect、stats、start、stop、restart。容器图标优先使用 Unraid metadata，缺失时使用通用容器图标，不联网检索 Logo。2026-10-25 已在 Unraid 7.1.0 核实 `docker.json` 的 `icon` 和本地 PNG 缓存来源，Home 已按固定目录和大小白名单读取；实现约束见 README 和[验证记录](validation/2026-10-25-home-docker/report.md)。Home 另支持可选的 FolderView2 配置读取，按插件成员规则合并文件夹并使用配置图标，需增加窄范围只读挂载；HTTPS PNG 由浏览器直接读取且不携带认证，后端不代理，详见[FolderView2 验证](validation/2026-10-25-folderview2/report.md)。

当前 Docker 只读实现每两秒调用 Engine list、inspect、非流式 stats 并保存快照，`GET /docker` 只读缓存。前端每两秒轮询，后台暂停，恢复可见后刷新；本阶段不扩展 System SSE 协议。快照包含 `timestamp`、`available`、`reason`、`containers`、`summary`、`diagnostics`。每个容器返回白名单字段：`id`、`name`、`state`、`cpuUsage`、`memoryUsedBytes`、`memoryLimitBytes`、`uptimeSeconds`、`networkRXRate`、`networkTXRate`、`diagnostics`。未知指标返回 `null`，列表成功但个别容器统计失败不使整个模块不可用。CPU 与网络速率依赖有效相邻计数器，首次、计数回退、重启或采集恢复时重建基线。内存采用 usage 扣除 inactive_file，cgroup v1 可回退 cache。

`capabilities.docker` 在此阶段仅表示读取可用；新增 `dockerActions.start/stop/restart` 表达独立写能力，默认均为 `false`。当前不接入写执行器或操作按钮。生产模板保持 `Privileged=false`，可选只读挂载 Docker socket；只读 bind 模式本身不限制 socket API 权限。前端沿用现有单页，展示全部 Running、默认折叠的 Stopped，以及暂停和过渡状态 Other；Running 折叠偏好保存到 localStorage。Unraid 图标数据源未验证，使用本地通用容器图标；独立路由和操作 Sheet 留待相应阶段。

### VM

VM 写操作仅为后续目标，UI 名称使用 “Force Stop”，不得暴露 `destroy` 这一底层术语。当前人工验收只使用下述只读连接，不访问可写 socket 或调用启停接口。

当前阶段补齐 VM 只读预览。使用纯 Go libvirt 客户端，仅连接 `/var/run/libvirt/libvirt-sock-ro`，URI 固定为 `qemu:///system`，不回退到可写 socket 或 CLI。生产模板可选只读挂载 `/var/run/libvirt`，保持 `Privileged=false`；真实主机兼容性尚未验证，`VM_READ_ENABLED` 默认关闭，只有显式设为 `true` 才采集，供测试主机验证。每轮采集限时六秒，列表超过 1,024 个 VM 时报告不可用。

后端每三秒采集并缓存 `timestamp`、`available`、`reason`、`domains`、`summary` 和 `diagnostics`，`GET /vms` 只读缓存。每个 VM 仅返回 `id`（UUID）、`name`、`state`、`vcpus`、`memoryBytes`、`uptimeSeconds` 和 `diagnostics`。CPU 采用 XML 中当前分配数量，内存采用 `currentMemory`，缺失时回退到 `memory`，按声明单位转为字节；两者均为分配资源，不表示实时使用量。不导出 XML、设备路径或 metadata。单个 VM 的详情读取失败时保留该行，受影响字段返回 `null` 并附诊断。尚无可靠开机时间来源，uptime 返回 `null`，不把累计 vCPU 时间当作运行时长。

`capabilities.vm` 只表达缓存中的读取可用性，独立的 `vmActions.start/stop/forceStop` 默认关闭；读取成功不授予写权限。本阶段没有 VM 执行器、动作路由或操作按钮。

前端沿用现有单页，每三秒轮询，后台暂停，返回前台时刷新，卸载时取消请求。VM 按 Running、Stopped 和 Other 分组；只有 shutoff 归入 Stopped，默认折叠。卡片显示采样时间、未知指标和诊断；请求失败保留上次快照。System SSE 协议保持不变。真实主机读取验证及 VM 写操作留待后续阶段。

### Array、Parity 与 Storage

可替换 Provider 和动作接口属于后续设计，不作为当前只读验收的前置。当前通过主应用 `/storage` 与 Unraid WebGUI 对照 Array、Parity、Pool、Disk 的已有读取结果，记录数据来源、可观察字段与缺失原因；不尝试其他控制入口，不新增 Provider 或诊断能力。

Provider 不能为兼容性临时拼接任意 shell 命令。若确实需要系统命令，命令、参数和工作目录必须在代码中静态定义，调用者没有注入入口。

## 前端架构

前端使用 React 19、TypeScript、Vite、TanStack Router、TanStack Query、shadcn/ui、Tailwind CSS v4、Motion、Lucide 和 Sonner。

状态归属固定如下：

| 状态 | 归属 |
|---|---|
| 服务端快照和 SSE 增量 | TanStack Query |
| Bottom Sheet、选中资源和交互状态 | 组件本地 state / context |
| 主题和轻量偏好 | localStorage |

MVP 不引入 Zustand。路由按页面懒加载；首页首屏只加载 Home 必要代码。Sparkline 用最多 60 点的 SVG path / polyline 绘制，不引入大型图表库。

前端在 SSE 到达时按事件类型合并 Query Cache，不覆盖未包含字段。操作提交后立刻显示本地的“已提交”反馈，后续状态以 `operation.updated` 和资源状态事件为准。普通失败用 Toast，资源级失败用行内状态，高风险 Array 操作用完整结果视图。

PWA 使用 `display: standalone`，处理顶部和底部安全区域。Service Worker 仅缓存应用壳和静态资源，明确排除 `/api/*` 与 `/healthz`。

## 安全要求

- 禁止提供 `/exec`、任意 URL 代理、任意文件读写和任意 shell API。
- 每个动作都有固定业务接口与服务端资源白名单。
- 权限、Provider 可用性和资源当前状态必须在执行前再次校验，不能只依赖前端禁用按钮。
- 所有操作记录 operation ID、资源、动作、开始和结束时间、结果与错误码；日志不得记录 `APP_TOKEN`。
- API 响应不返回宿主机敏感配置文件内容、Docker 环境变量或 VM XML 的完整原文。
- CORS 默认同源关闭；若未来加入独立前端源，必须显式白名单。

## 主应用人工验收

按 README 部署现有主应用，在授权的 Unraid 主机上打开 Home / Docker / VM / Storage，并对照对应 WebGUI 页面。必要时查看现有 `/api/v1/capabilities`、`/api/v1/system`、`/api/v1/docker`、`/api/v1/vms`、`/api/v1/storage` 快照。只验收已实现的读取，不运行独立程序、脚本或写操作。

`GET /healthz` 的 `204` 只表示进程存活。采集失败仍可能返回 HTTP `200`，必须检查 `available`、`reason`、`diagnostics`、可为 `null` 的指标与采样时间；旧快照和空配置不代表当前读取成功。断线、后台恢复和刷新失败时，页面应保留旧样本及时间，明确标注旧数据，成功刷新后撤下标记。

| 能力 | 人工对照内容与限制 |
|---|---|
| CPU / 内存 | 对齐采样时间和统计口径；CPU 首样本、回退或恢复为 `null`，内存采用 `MemTotal - MemAvailable` |
| 网络 | 按主应用显示的接口名称，在 WebGUI 选择同一接口，再按 `B/s × 8 / 1000` 换算 Kbps；连续观察同一时间窗口，不凭单截图判定精度，不合计桥、bond 与成员 |
| Docker | 对照列表、状态及可用资源统计；首样本、重启或恢复时速率可为 `null`，局部失败保留行；不启停或重启容器 |
| VM | 默认不连接；授权后显式设置 `VM_READ_ENABLED=true` 并只读挂载 `/var/run/libvirt`，仅使用 `libvirt-sock-ro`；对照状态和分配 CPU / 内存，uptime 未知为 `null`，不调用动作 |
| Array / Parity | 对照已有状态和进度字段；不可观察项记为未验证，不为验收启动、停止阵列或发起、取消校验 |
| Pool / Disk | 对照容量口径、分组、电源状态和 I/O；阵列停止或容量不完整为 `null`，Pool 容量只计一次 |
| 温度 | 核对主应用已有传感器映射；休眠盘温度为 `null`、显示 `Temp —`，不唤醒磁盘、不运行 SMART |

记录主机版本、部署版本、只读挂载、采样时间、实际差异及未验证项。合成测试不能代替真实主机验收；读取通过不证明写操作安全，也不改变默认权限。VM 真实主机读取与 Android / iOS PWA 仍须分别验收，未验证不能称可用。

## 开发顺序与完成标准

以下保留研发顺序，不表示各项已完成；主应用人工验收随已有只读能力进行，不另设前置交付物。

1. 后端基础：服务启动、能力状态、快照 API、采样、SSE、Docker / VM / Storage adapter。
2. 前端基础：主题、组件、查询层、错误和断线状态。
3. Home 与独立只读页：完成快照和状态展示，对照 Unraid WebGUI 验收读取。
4. Operations：后续单独验证控制入口、最小权限与实际完成状态后，才考虑接入执行器；人工读取验收期间写能力保持关闭。
5. PWA 收尾：安装、safe area、后台恢复、横竖屏和移动端性能，按 README 做真实设备验收。

达到 MVP 的最低技术验收线：局域网首次可操作时间小于 2 秒；交互反馈小于 100 毫秒；指标延迟小于 2 秒；操作提交后 200 毫秒内给出已提交状态；任何不可用能力都有明确的 UI 和 API 表达。
